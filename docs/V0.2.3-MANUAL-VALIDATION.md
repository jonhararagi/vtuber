# V0.2.3 — Validación manual de Windows

**Estado:** pendiente de ejecución humana. Esta guía no implica aceptación de V0.2.3.

## Paquete que se va a probar

1. Abre la ejecución de [Windows CI](https://github.com/jonhararagi/vtuber/actions/runs/38153141956) y descarga el artefacto `VTuberBot-V0.2.3-win-x64-8289bda51fe5a4f0ad57bf375cc3d6d62409fc38`.
2. Extrae su contenido en una carpeta nueva y escribible, por ejemplo `Documentos\VTuberBot-V0.2.3-Test`. No copies bases de datos, configuraciones ni logs de otra instalación.
3. Comprueba que contiene `VtuberBot.App.exe` y `BUILD-INFO.txt`. Lee el SHA de origen que aparece en el archivo y guárdalo junto al resultado de la prueba.

**Esperado:** extracción sin errores, ejecutable y BUILD-INFO presentes.  
**Fallo:** ZIP corrupto, ejecutable ausente o SHA que no coincide con la ejecución que descargaste.

## Pruebas

Registra cada paso como **APROBADO**, **FALLIDO** o **NO EJECUTADO**. Si falla, anota el mensaje literal y el paso.

| Paso | Acción | Resultado esperado | Criterio de fallo |
|---|---|---|---|
| 1 | Ejecutar `VtuberBot.App.exe` | Se abre la ventana principal sin cierre inesperado | No abre, se cierra o muestra una excepción no controlada |
| 2 | Pulsar **Iniciar** | El estado cambia a iniciado/activo y la interfaz sigue respondiendo | Bloqueo, excepción o estado incoherente |
| 3 | Pulsar **Detener** | El estado indica detenido y la ventana continúa respondiendo | Bloqueo, excepción o estado incoherente |
| 4 | Ejecutar `help` | Se muestra la ayuda de comandos | Error no controlado o no aparece una respuesta de ayuda |
| 5 | Ejecutar `status` | Se muestra el estado de la aplicación | Error no controlado o no aparece una respuesta de estado |
| 6 | Ejecutar `ping` | Se obtiene la respuesta definida por el router de comandos, esperada como `pong` | Error no controlado o no se obtiene la respuesta prevista |
| 7 | Repetir **Iniciar/Detener** al menos 5 veces | Cada ciclo termina sin bloqueo ni excepción no controlada | Cualquier ciclo deja la app bloqueada o en estado incoherente |
| 8 | Mantener la app activa durante 10 minutos | Sigue respondiendo; no hay cierres inesperados ni errores nuevos atribuibles a la app | Cierre, bloqueo, excepción no controlada o crecimiento de recursos claramente anormal |
| 9 | Cerrar la ventana | La ventana se cierra y el proceso termina | El proceso permanece ejecutándose sin una razón esperada |

No se han definido umbrales numéricos de CPU o RAM para esta versión. Registra las observaciones, pero no inventes un límite de aceptación. Si la aplicación escribe logs, revisa los generados dentro de la carpeta de prueba y anota cualquier excepción relevante.

## Evidencias que deben registrarse

- Fecha, versión de Windows y SHA de origen del paquete.
- Resultado de cada paso y cualquier mensaje de error literal.
- Si la prueba de diez minutos se completó íntegramente.
- Si el proceso terminó después de cerrar la ventana.
- Incidencias y, si es posible, capturas de pantalla o extractos de log sin secretos ni datos personales.

## Qué demuestra cada tipo de verificación

- **CI:** restore, build Release, pruebas automatizadas y empaquetado ejecutados en la ejecución enlazada.
- **Verificación remota:** rama, commit de origen registrado, metadatos del artefacto y validaciones del ZIP realizadas por el workflow.
- **Validación manual:** apertura e interacción real de WPF, ciclos repetidos, ejecución de diez minutos y cierre de proceso en Windows.
- **Bloqueo de aceptación:** cualquier fallo reproducible de los pasos requeridos o ausencia de evidencia para una prueba obligatoria.

V0.2.3 solo puede marcarse como aceptada cuando la lista manual esté completa, las incidencias bloqueantes estén resueltas y las evidencias estén documentadas.
